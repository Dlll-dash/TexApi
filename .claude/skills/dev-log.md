# 开发日志 Skill

当用户要求写开发日志、记录今日成果、或类似表述时，执行以下流程。

## 流程

### 1. 读取今日成果

- `git log --oneline -5` — 查看最近提交
- `git show --stat HEAD` — 如果最新提交是今天的，展示文件变更统计
- `git log --since="today" --oneline` — 确认今天所有提交

### 2. 读取 Plan 进度

- `Glob .claude/*.md` 和 `Glob .claude/**/*.md` — 扫描所有可能的计划文件
- 根据当前对话上下文，判断哪些计划与今天的工作相关
- 对照 git 提交记录和今天工作内容，标注相关计划的完成状态：✅ 完成 / 🔶 部分完成 / ❌ 未开始

### 3. 命名规则

文件名格式：`log/M.DD开发日志.md`

- M = 月份（无前导零，如 `8`）
- DD = 日期（有前导零，如 `02`）
- 例：`log/8.02开发日志.md`、`log/8.15开发日志.md`、`log/12.01开发日志.md`

### 4. 写入文件

创建 `log/` 目录（如不存在），写入 `log/M.DD开发日志.md`。

## 日志模板

```markdown
# 开发日志

## YYYY-MM-DD

### 今日成果

**Commit**: `<commit-hash>` — <commit-message>

**改动量**: N 个文件，+X 行，-Y 行

#### 1. <任务一标题>

- <具体改动点>
- ...

#### 2. <任务二标题>

- ...

### 当前 Plan 进度

> 相关计划文件：<列出本次参考的 plan 文件路径>

<按实际计划结构列出进度，不预设固定格式>

**整体进度**：<根据实际情况估算>

### 明日计划

<从相关 plan 中提取下一个待做任务，或根据当前对话上下文合理建议>
```

## 注意

- 如果今天没有新提交，读取 `git diff --stat` 看未提交的改动
- 不要写死某个 Plan 文件名——每次扫描 `.claude/` 下的文件，结合对话上下文判断
- 进度百分比根据实际情况计算
- 明日计划优先延续当天未完成的工作，再推进下一步
